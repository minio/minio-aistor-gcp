## Overview

When users deploy MinIO AIStor from GCP Marketplace, they see a streamlined configuration form with essential parameters only. This simplified approach makes deployment easier while using optimal defaults for advanced settings.

**Parameter Design**:
- ✅ 9 core configurable parameters
- ✅ Resource limits use Helm chart defaults
- ✅ Service types default to LoadBalancer
- ✅ Storage class uses cluster default
- ✅ Metrics enabled by default
- ✅ Auto-generated TLS certificates

## Required Parameters

These parameters **must** be provided by the user during deployment:

### 1. Application Name
- **Field**: `name`
- **Type**: String
- **Default**: `minio-aistor`
- **Description**: The name of the MinIO AIStor application instance
- **Example**: `my-minio-cluster`, `prod-storage`

### 2. Namespace
- **Field**: `namespace`
- **Type**: String (GCP Marketplace namespace selector)
- **Description**: The Kubernetes namespace where MinIO AIStor will be deployed
- **Note**: Can create new or use existing namespace

### 3. AIStor License Key ⚠️ **REQUIRED**
- **Field**: `license`
- **Type**: String (text input)
- **Format**: JWT token (starts with 'eyJ')
- **Description**: MinIO AIStor Enterprise license key
- **How to Get**: Contact MinIO at https://min.io/contact
- **Example**: `eyJhbGciOiJFUzM4NCIsInR5cCI6IkpXVCJ9...`
- **Important**: Use the decoded JWT token, not base64-encoded block

## Cluster Configuration

### Number of Servers
- **Field**: `aistor-objectstore.objectStore.pools.0.servers`
- **Type**: Integer
- **Default**: `4`
- **Minimum**: `4`
- **Maximum**: `32`
- **Description**: Number of MinIO server replicas to deploy
- **Note**: Minimum 4 required for distributed mode (production)
- **Example**: `4`, `8`, `16`

### Volumes per Server
- **Field**: `aistor-objectstore.objectStore.pools.0.volumesPerServer`
- **Type**: Integer
- **Default**: `4`
- **Minimum**: `1`
- **Maximum**: `16`
- **Description**: Number of storage volumes attached to each MinIO server
- **Calculation**: Total volumes = servers × volumesPerServer
- **Example**: 4 servers × 4 volumes = 16 total volumes

### Storage Size per Volume
- **Field**: `aistor-objectstore.objectStore.pools.0.size`
- **Type**: String
- **Default**: `10Gi`
- **Pattern**: Must match `^[1-9][0-9]*(\.[0-9]+)?[GT]i$`
- **Description**: Size of persistent volume for each volume attachment
- **Valid Examples**: `10Gi`, `100Gi`, `1Ti`, `5Ti`
- **Total Storage**: size × volumes × servers
  Example: 10Gi × 4 × 4 = 160Gi

## Credentials

### Root Access Key (Username)
- **Field**: `aistor-objectstore.secrets.accessKey`
- **Type**: String
- **Default**: `admin`
- **Description**: MinIO root access key (username for login)
- **Example**: `admin`, `minio-admin`

### Root Secret Key (Password)
- **Field**: `aistor-objectstore.secrets.secretKey`
- **Type**: GENERATED_PASSWORD (auto-generated by GCP)
- **Length**: 32 characters
- **Symbols**: No symbols (alphanumeric only)
- **Description**: MinIO root secret key (password) - auto-generated
- **Note**: GCP automatically generates a secure password

## Default Settings (Not Configurable)

The following settings use optimal defaults from Helm chart values:

### Resource Allocation
- **Memory Request**: 2Gi per server (from Helm chart)
- **CPU Request**: 1 core per server (from Helm chart)
- **Memory Limit**: 4Gi per server (from Helm chart)
- **CPU Limit**: 2 cores per server (from Helm chart)

### Network Services
- **API Service Type**: LoadBalancer (for external S3 API access)
- **Console Service Type**: LoadBalancer (for web console access)

### Storage
- **Storage Class**: Uses GKE default storage class (typically `standard-rwo`)
- **Pool Name**: `pool-0` (auto-assigned)

### Security & Monitoring
- **TLS Certificate**: Auto-generated self-signed certificate
- **Metrics**: Enabled (Prometheus-compatible endpoint)

## Cluster Requirements

Enforced by GCP Marketplace (defined in `clusterConstraints`):

### Minimum Cluster Size
- **Nodes**: Minimum 4 nodes recommended
- **Reason**: Anti-affinity rules spread pods across nodes for HA
- **Per-Pod Resources**:
  - CPU Request: 1000m (1 core)
  - Memory Request: 2Gi
  - Replicas: 4 (default)

### Node Affinity
- **Type**: `REQUIRE_ONE_NODE_PER_REPLICA`
- **Effect**: Each MinIO pod scheduled on a different node

## Total Resource Calculation

### Formula
```
Total CPU Request = servers × 1 core
Total Memory Request = servers × 2Gi
Total Storage = servers × volumesPerServer × size
Total PVCs = servers × volumesPerServer
```

### Default Configuration (4 servers)
```
CPU Request: 4 × 1 core = 4 cores
Memory Request: 4 × 2Gi = 8Gi
Storage: 4 × 4 × 10Gi = 160Gi
PVCs: 4 × 4 = 16 volumes
```

## Parameter Validation

### Automatic Validation

GCP Marketplace validates:
- ✅ License key is provided
- ✅ Server count (4-32)
- ✅ Storage size format (matches pattern)
- ✅ Required fields are provided

### Common Validation Errors

**Invalid Storage Size**:
- Error: `pattern: ^[1-9][0-9]*(\.[0-9]+)?[GT]i$`
- Fix: Use format like `10Gi`, `100Gi`, or `1Ti`

**Too Few Servers**:
- Error: `minimum: 4`
- Fix: MinIO distributed mode requires at least 4 servers

**Missing License**:
- Error: `required: license`
- Fix: Provide valid MinIO AIStor Enterprise license (JWT format)

## After Deployment

### Accessing Credentials

Retrieve the auto-generated password:
```bash
kubectl get secret minio-aistor-env-config \
  -n <namespace> \
  -o jsonpath='{.data.config\.env}' | base64 -d
```

### Getting Service URLs

For LoadBalancer (default):
```bash
kubectl get svc -n <namespace>
# Look for EXTERNAL-IP for minio-aistor-hl and minio-aistor-console services
```

Access:
- **S3 API**: `http://<EXTERNAL-IP>:9000`
- **Web Console**: `http://<EXTERNAL-IP>:9001`

### Checking Deployment Status

```bash
# Check ObjectStore resource
kubectl get objectstore -n <namespace>

# Check pods
kubectl get pods -n <namespace>

# Check operator
kubectl get pods -n <namespace> -l app.kubernetes.io/name=aistor-objectstore-operator
```

## Advanced Configuration

### Customizing Advanced Settings

To customize resource limits or other advanced settings not exposed in the GCP Marketplace schema, you can use the underlying Helm chart directly:

```bash
helm install minio-aistor ./chart/minio-aistor \
  --namespace minio \
  --create-namespace \
  --set license="<license>" \
  --set aistor-objectstore.objectStore.pools[0].servers=4 \
  --set aistor-objectstore.objectStore.pools[0].resources.requests.memory="4Gi" \
  --set aistor-objectstore.objectStore.pools[0].resources.requests.cpu="2"
```

See the `chart/minio-aistor/values.yaml` file for all available options.

## Important Notes

### License Requirement ⚠️
- **Critical**: Users MUST provide a valid MinIO AIStor Enterprise license
- Without license, deployment will fail or cluster won't start
- License must be in JWT format (starts with 'eyJ')
- Contact MinIO: https://min.io/contact

### Minimum Cluster Size
- **GKE Cluster**: Should have at least 4 nodes
- **Node Type**: Recommended n1-standard-4 or better
- **Reason**: Anti-affinity spreads pods across nodes for HA

### Storage Considerations
- PVCs are created dynamically from default storage class
- Cannot reduce volume size after creation
- Plan storage capacity for growth
- For high-performance workloads, use premium storage class nodes

### Cost Estimation
- **Compute**: Based on server count (1 core + 2Gi per server)
- **Storage**: Based on total storage (servers × volumes × size)
- **LoadBalancer**: 2 Load Balancers (API + Console) incur costs
- **Data Transfer**: If accessing externally
