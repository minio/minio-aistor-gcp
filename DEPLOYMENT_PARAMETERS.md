# MinIO AIStor - GCP Marketplace Deployment Parameters

**Version**: 1.0.0
**Last Updated**: 2025-01-07

---

## Overview

When users deploy MinIO AIStor from GCP Marketplace, they will see a configuration form with the following parameters. These are defined in `schema.yaml` and will be presented in the GCP Marketplace UI.

---

## Required Parameters

These parameters **must** be provided by the user:

### 1. Application Name
- **Field**: `name`
- **Type**: String
- **Default**: `minio-aistor`
- **Description**: The name of the MinIO AIStor application instance
- **Example**: `my-minio-cluster`

### 2. Namespace
- **Field**: `namespace`
- **Type**: String (GCP Marketplace will show namespace selector)
- **Description**: The Kubernetes namespace where MinIO AIStor will be deployed
- **Note**: Can create new or use existing namespace

### 3. AIStor License Key ⚠️ **REQUIRED**
- **Field**: `license`
- **Type**: String (text input)
- **Minimum Length**: 100 characters
- **Format**: JWT token (starts with 'eyJ')
- **Description**: MinIO AIStor Enterprise license key
- **How to Get**: Contact MinIO at https://min.io/contact
- **Example**: `eyJhbGciOiJFUzM4NCIsInR5cCI6IkpXVCJ9...`
- **Important**: Use the decoded JWT token, not base64-encoded

### 4. Service Account
- **Field**: `serviceAccount`
- **Type**: Service Account (auto-generated by GCP)
- **Description**: Service account for MinIO AIStor Operator and Object Store
- **Permissions**: Automatically configured with required RBAC roles

### 5. Reporting Secret
- **Field**: `reportingSecret`
- **Type**: Reporting Secret (auto-generated by GCP)
- **Description**: Used for GCP Marketplace usage reporting
- **Note**: Automatically created, no user input needed

## Cluster Configuration

### Number of Servers
- **Field**: `aistor-objectstore.objectStore.pools[0].servers`
- **Type**: Integer
- **Default**: `4`
- **Minimum**: `4`
- **Maximum**: `32`
- **Description**: Number of MinIO server replicas to deploy
- **Note**: Minimum 4 for distributed mode (production). Cannot upgrade from standalone (1) to distributed mode.
- **Example**: `4`, `8`, `16`

### Volumes per Server
- **Field**: `aistor-objectstore.objectStore.pools[0].volumesPerServer`
- **Type**: Integer
- **Default**: `4`
- **Minimum**: `1`
- **Maximum**: `16`
- **Description**: Number of storage volumes attached to each MinIO server
- **Calculation**: Total volumes = servers × volumesPerServer
- **Example**: 4 servers × 4 volumes = 16 total volumes

### Storage Size per Volume
- **Field**: `aistor-objectstore.objectStore.pools[0].size`
- **Type**: String
- **Default**: `10Gi`
- **Pattern**: Must match `^[1-9][0-9]*(\.[0-9]+)?[GT]i$`
- **Description**: Size of persistent volume for each volume attachment
- **Valid Examples**: `10Gi`, `100Gi`, `1Ti`, `5Ti`
- **Total Storage**: size × volumes × servers (e.g., 10Gi × 4 × 4 = 160Gi)

---

## Resource Limits

### Memory Request
- **Field**: `aistor-objectstore.objectStore.pools[0].resources.requests.memory`
- **Type**: String
- **Default**: `2Gi`
- **Pattern**: Must match `^[1-9][0-9]*(\.[0-9]+)?[MGT]i$`
- **Description**: Memory resource request per MinIO server
- **Examples**: `2Gi`, `4Gi`, `8Gi`

### CPU Request
- **Field**: `aistor-objectstore.objectStore.pools[0].resources.requests.cpu`
- **Type**: String
- **Default**: `1000m` (1 CPU core)
- **Pattern**: Must match `^[1-9][0-9]*(m|(\.[0-9]+))?$`
- **Description**: CPU resource request per MinIO server
- **Examples**: `1000m`, `2000m`, `1`, `2`

### Memory Limit
- **Field**: `aistor-objectstore.objectStore.pools[0].resources.limits.memory`
- **Type**: String
- **Default**: `4Gi`
- **Pattern**: Must match `^[1-9][0-9]*(\.[0-9]+)?[MGT]i$`
- **Description**: Memory resource limit per MinIO server
- **Examples**: `4Gi`, `8Gi`, `16Gi`

### CPU Limit
- **Field**: `aistor-objectstore.objectStore.pools[0].resources.limits.cpu`
- **Type**: String
- **Default**: `2000m` (2 CPU cores)
- **Pattern**: Must match `^[1-9][0-9]*(m|(\.[0-9]+))?$`
- **Description**: CPU resource limit per MinIO server
- **Examples**: `2000m`, `4000m`, `2`, `4`

## Credentials

### Root Access Key (Username)
- **Field**: `aistor-objectstore.secrets.accessKey`
- **Type**: String
- **Default**: `admin`
- **Minimum Length**: 3 characters
- **Description**: MinIO root access key (username for login)
- **Example**: `admin`, `minio-admin`, `root`

### Root Secret Key (Password)
- **Field**: `aistor-objectstore.secrets.secretKey`
- **Type**: GENERATED_PASSWORD (auto-generated by GCP)
- **Length**: 32 characters
- **Symbols**: No symbols (alphanumeric only)
- **Base64**: Not encoded
- **Description**: MinIO root secret key (password) - auto-generated if not provided
- **Note**: GCP will automatically generate a secure password. Users can override if needed.

---

## Service Configuration

### MinIO API Service Type
- **Field**: `aistor-objectstore.objectStore.services.minio.serviceType`
- **Type**: Enum (dropdown)
- **Default**: `LoadBalancer`
- **Options**:
  - `LoadBalancer` - Exposes service externally with GCP Load Balancer
  - `ClusterIP` - Internal cluster access only
  - `NodePort` - Exposes on each node's IP
- **Description**: Kubernetes service type for MinIO S3 API endpoint
- **Recommendation**: Use `LoadBalancer` for external access

### MinIO Console Service Type
- **Field**: `aistor-objectstore.objectStore.services.console.serviceType`
- **Type**: Enum (dropdown)
- **Default**: `LoadBalancer`
- **Options**:
  - `LoadBalancer` - Exposes web console externally
  - `ClusterIP` - Internal cluster access only
  - `NodePort` - Exposes on each node's IP
- **Description**: Kubernetes service type for MinIO Web Console
- **Recommendation**: Use `LoadBalancer` for web access

## Optional Parameters

### Storage Class Name
- **Field**: `aistor-objectstore.objectStore.pools[0].storageClassName`
- **Type**: String
- **Default**: `""` (empty = use default storage class)
- **Description**: Kubernetes StorageClass for persistent volumes
- **GKE Options**:
  - `standard-rwo` - Standard persistent disks
  - `premium-rwo` - SSD persistent disks
  - Leave empty to use cluster default
- **Example**: `premium-rwo`

### Enable Metrics
- **Field**: `aistor-objectstore.objectStore.metrics.enabled`
- **Type**: Boolean (checkbox)
- **Default**: `true`
- **Description**: Enable Prometheus-compatible metrics endpoint
- **Recommendation**: Keep enabled for monitoring

### TLS Certificate
- **Field**: `certificate`
- **Type**: TLS_CERTIFICATE (special GCP type)
- **Default**: Auto-generated certificate
- **Description**: TLS certificate for MinIO
- **Note**: If not provided, uses auto-generated self-signed certificate
- **Advanced**: Users can provide custom certificate for production

## Cluster Requirements

These are enforced by GCP Marketplace (defined in `clusterConstraints`):

### Minimum Cluster Size
- **Nodes**: Minimum 4 nodes required
- **Reason**: Each MinIO server prefers a separate node (anti-affinity)

### Per-Pod Resources
- **CPU Request**: 1000m (1 core)
- **Memory Request**: 2Gi
- **Replicas**: 4 (minimum)

### Node Affinity
- **Type**: `REQUIRE_ONE_NODE_PER_REPLICA`
- **Effect**: Each MinIO pod scheduled on different node for HA

## Total Resource Calculation

### Formula
```
Total CPU Request = servers × cpu.request
Total Memory Request = servers × memory.request
Total Storage = servers × volumesPerServer × size
Total PVCs = servers × volumesPerServer
```

### Default Configuration (4 servers)
```
CPU Request: 4 × 1000m = 4 cores
Memory Request: 4 × 2Gi = 8Gi
Storage: 4 × 4 × 10Gi = 160Gi
PVCs: 4 × 4 = 16 volumes
```

## Parameter Validation

### Automatic Validation

GCP Marketplace validates:
- ✅ License key length (minimum 100 characters)
- ✅ Server count (4-32)
- ✅ Storage size format (must match pattern)
- ✅ Resource limit format (must match pattern)
- ✅ Service type (must be one of enum values)
- ✅ Required fields are provided

### Common Validation Errors

**License Key Too Short**:
- Error: "minLength: 100"
- Fix: Ensure full JWT token is provided (not truncated)

**Invalid Storage Size**:
- Error: "pattern: ^[1-9][0-9]*(\.[0-9]+)?[GT]i$"
- Fix: Use format like `10Gi`, `100Gi`, or `1Ti`

**Invalid CPU Format**:
- Error: "pattern: ^[1-9][0-9]*(m|(\.[0-9]+))?$"
- Fix: Use `1000m` or `1` (not `1000` without m)

**Too Few Servers**:
- Error: "minimum: 4"
- Fix: MinIO distributed mode requires at least 4 servers

## Parameter Dependencies

### If servers = 4:
- Recommended volumesPerServer: 4
- Minimum memory: 2Gi per server
- Minimum CPU: 1 core per server

### If using LoadBalancer:
- GCP will provision external IP
- Costs apply for Load Balancer
- External access enabled

### If using ClusterIP:
- No external IP
- Port-forward required for access
- No additional Load Balancer costs

### If storageClassName is empty:
- Uses GKE default storage class
- Typically `standard-rwo` on GKE

## After Deployment

### Accessing Credentials

Users can retrieve credentials:
```bash
kubectl get secret minio-aistor-env-config \
  -n <namespace> \
  -o jsonpath='{.data.config\.env}' | base64 -d
```

### Getting Service URLs

For LoadBalancer:
```bash
kubectl get svc -n <namespace>
# Get EXTERNAL-IP for minio and minio-aistor-console services
```

For ClusterIP:
```bash
kubectl port-forward -n <namespace> svc/minio 9000:9000
kubectl port-forward -n <namespace> svc/minio-aistor-console 9443:9443
```

### Checking Deployment

```bash
# Check ObjectStore status
kubectl get objectstore -n <namespace>

# Check pods
kubectl get pods -n <namespace>

# Check cluster info
mc admin info <alias>
```

## Important Notes

### License Requirement ⚠️
- **Critical**: Users MUST provide a valid MinIO AIStor Enterprise license
- Without license, deployment will fail or cluster won't start
- License must be in JWT format (starts with 'eyJ')
- Contact MinIO: https://min.io/contact

### Minimum Cluster Size
- **GKE Cluster**: Must have at least 4 nodes
- **Reason**: Anti-affinity rules spread pods across nodes
- **Recommendation**: Use n1-standard-4 or better

### Storage Considerations
- PVCs are created dynamically
- Cannot reduce volume size after creation
- Plan storage capacity for growth
- Consider using premium-rwo for performance

### Cost Estimation
- Compute: Based on CPU/memory requests
- Storage: Based on total storage (servers × volumes × size)
- LoadBalancer: Additional cost if used
- Data transfer: If accessing externally
